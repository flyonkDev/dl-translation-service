# CLAUDE.md

Guidance for AI coding agents working in this repo. Complements — does not replace — [AGENTS.md](AGENTS.md) (which holds product vision, rules, roadmap). This file documents **how the code actually looks today** so an agent can navigate without re-exploring.

---

## Product in one paragraph

Commercial web service that generates an **IDP Companion PDF** (a courtesy translation/companion document — *not* an official government International Driving Permit). Landing → SPA form → OCR verify → payment → PDF download. Sold as one-off purchase per plan duration (1 / 3 / 5 years).

MVP launch target: ~1 month. Solo dev (@flyonk). Bias toward "simple but reliable" over "elegant but complex". Do not overengineer.

## End-to-end flow (as actually wired)

1. **Landing** ([apps/landing/components/widgets/StartApplicationWidget.vue](apps/landing/components/widgets/StartApplicationWidget.vue)) — user picks country + plan, click builds `${appUrl}/apply?issueCountry=XX&planYears=N&locale=xx` and redirects to the SPA. Stateless URL handoff — no cookie/session.

2. **SPA `/apply`** ([apps/frontend/src/pages/DriverLicenseApplicationPage.vue](apps/frontend/src/pages/DriverLicenseApplicationPage.vue)) — single long page that renders Step 1 (form + uploads + signature) and Step 3 (download after payment).
   - Router reads `?locale=` once and persists to `localStorage['idp.locale']` ([apps/frontend/src/app/router/index.ts:37-69](apps/frontend/src/app/router/index.ts#L37-L69)).
   - License image goes to `POST /api/verify/license` (OCR, returns `passed|review|failed` + `verificationId`).
   - Form submit → `POST /api/applications` (multipart; license `verificationId`, headshot file, form fields) → returns `{ applicationId, nextAction: 'payment' }`.
   - Router pushes `/payment/:applicationId`.

3. **SPA `/payment/:id`** ([apps/frontend/src/pages/PaymentPage.vue](apps/frontend/src/pages/PaymentPage.vue)) — **today: Gumroad-only, hardcoded URLs per plan** (lines ~140-194). Listens for `window.onGumroadPurchaseComplete` client-side callback to flip `isPaid = true`. No polling, no webhook awareness on the client. After confirmation, downloads via `GET /api/applications/:id/pdf?disposition=attachment`.

4. **Backend** ([apps/backend/src/applications/applications.service.ts](apps/backend/src/applications/applications.service.ts)) — persists the Application row with `status: 'created'`; runs face-match (AWS Rekognition) between license photo and headshot.

5. **Payment confirmation (backend)** — Gumroad → `POST /api/payments/gumroad/webhook?token=...` ([apps/backend/src/payments/providers/gumroad-webhook.controller.ts](apps/backend/src/payments/providers/gumroad-webhook.controller.ts)) → flips `Application.status` to `paid`, optionally emails PDF via Resend.

6. **PDF gating** ([apps/backend/src/applications/applications.service.ts:157-162](apps/backend/src/applications/applications.service.ts#L157-L162)) — if `REQUIRE_PAYMENT_FOR_PDF=1` and status is not `paid`/`pdf_ready` → 403. Otherwise PDF is generated on-demand with `pdf-lib` (no disk cache).

## Backend — key modules

[apps/backend/src/app.module.ts](apps/backend/src/app.module.ts) wires:

| Module | Endpoints | Notes |
|---|---|---|
| `PrismaModule` | — | Single Prisma client |
| `VerifyModule` | `POST /api/verify/license` | Tesseract.js OCR; writes to `uploads/verify/`; TTL 1h; state in in-memory `VerificationStore` |
| `ReferenceModule` | `GET /api/reference/{countries,pricing}` | Countries data generated by `npm run countries:generate` |
| `ApplicationsModule` | `POST /api/applications`, `GET /api/applications/:id/pdf` | Persists Application; generates PDF on demand |
| `PaymentsModule` | `POST /api/payments/gumroad/webhook` | Gumroad only (today) |
| `EmailModule` | — | Resend client; event-based tags |
| `FaceVerificationModule` | — | AWS Rekognition `CompareFaces`; threshold via `FACE_MATCH_SIMILARITY_THRESHOLD` |

### Prisma schema ([apps/backend/prisma/schema.prisma](apps/backend/prisma/schema.prisma))

One table: `Application`. No `Payment` table — **payment state lives solely in `Application.status`**.

```prisma
enum ApplicationStatus { created  paid  pdf_ready }
```

Gumroad sale metadata is **not persisted** (only emitted as Resend tags). Adding a real audit trail requires a new `Payment` table — worth doing when a second provider (e.g. crypto) lands.

## File storage

- License images — `uploads/verify/<uuid>.<ext>`, **TTL 1 hour** (VerificationStore cleans up).
- Headshots — `uploads/<ts-rand>.<ext>`, **no cleanup yet** (roadmap item). Path persisted in `Application.headshotPath`.
- PDFs — generated in-memory with pdf-lib, never written to disk.
- Base dir: `UPLOAD_DIR` env, default `./uploads`.

## Known gaps / tech-debt hotspots

Calling these out so an agent doesn't "rediscover" them and churn on fixes:

1. **Payment is Gumroad-coupled.** No `IPaymentProvider` abstraction. URLs are hardcoded on the frontend, single webhook controller on the backend. Adding a second provider (crypto, Paddle) means either (a) a parallel controller + a new frontend branch in `PaymentPage.vue`, or (b) a small abstraction refactor (provider registry + strategy). Pick (b) if you're adding a provider anyway — (a) is a short-term trap.
2. **No `Payment` table.** Gumroad sale_id is only a Resend email tag. Adding a second payment provider = perfect moment to persist `Payment { id, applicationId, provider, externalId, amount, currency, status, raw, createdAt }`.
3. **Webhook auth is a query-string shared secret**, not HMAC. Upgrade to HMAC when touching this area (standard for Paddle; required for most crypto gateways).
4. **No headshot cleanup.** Storage will grow unbounded. Low priority for MVP, high priority post-launch.
5. **German locale missing.** Trivial to add once strings are translated.
6. **PDF gating is a status check in service code.** Fine for MVP. If/when you touch auth, promote to a NestJS Guard.

## Coding rules (from AGENTS.md — condensed)

- TypeScript strict. Avoid `any`. Explicit types preferred.
- NestJS: DTO validation (class-validator).
- Frontend: Zod for runtime validation; vee-validate for forms.
- Respect FSD boundaries — no imports from a higher layer; flag violations, don't silently move files.
- Preserve existing API contracts unless explicitly asked to change them.
- Minimal changes. No new deps unless necessary.
- If unsure about architecture — ask.

## Hand-off tips for agents

- **Exploring?** Start with this file + `AGENTS.md`. The Explore agent is overkill for narrow questions — use Grep/Glob directly.
- **Changing payment?** Read [apps/frontend/src/pages/PaymentPage.vue](apps/frontend/src/pages/PaymentPage.vue) + [apps/backend/src/payments/providers/gumroad-webhook.controller.ts](apps/backend/src/payments/providers/gumroad-webhook.controller.ts) together — they're coupled by the applicationId-in-referrer convention.
- **Changing i18n?** Touch three places: `packages/i18n/index.ts` (constants), `apps/frontend/src/app/i18n/messages/*.ts`, `apps/landing/i18n/locales/*.json`.
- **Adding a backend module?** Wire it in [apps/backend/src/app.module.ts](apps/backend/src/app.module.ts); prefix routes with `/api/...` (global prefix is set in `main.ts`).
