## Product in one paragraph

Commercial web service that generates an **IDP Companion PDF** (a courtesy translation/companion document — *not* an official government International Driving Permit). Landing → SPA form → OCR verify → payment → PDF download. Sold as one-off purchase per plan duration (1 / 3 / 5 years).

MVP launch target: ~1 month. Solo dev (@flyonk). Bias toward "simple but reliable" over "elegant but complex". Do not overengineer.

## End-to-end flow (as actually wired)

1. **Landing** ([apps/landing/components/widgets/StartApplicationWidget.vue](apps/landing/components/widgets/StartApplicationWidget.vue)) — user picks country + plan, click builds `${appUrl}/apply?issueCountry=XX&planYears=N&locale=xx` and redirects to the SPA. Stateless URL handoff — no cookie/session.

2. **SPA `/apply`** ([apps/frontend/src/pages/DriverLicenseApplicationPage.vue](apps/frontend/src/pages/DriverLicenseApplicationPage.vue)) — single long page that renders Step 1 (form + uploads + signature) and Step 3 (download after payment).
   - Router reads `?locale=` once and persists to `localStorage['idp.locale']` ([apps/frontend/src/app/router/index.ts:37-69](apps/frontend/src/app/router/index.ts#L37-L69)).
   - License image goes to `POST /api/verify/license` (OCR, returns `passed|review|failed` + `verificationId`).
   - Form submit → `POST /api/applications` (multipart; license `verificationId`, headshot file, form fields) → returns `{ applicationId, nextAction: 'payment' }`.
   - Router pushes `/payment/:applicationId`.

3. **SPA `/payment/:id`** ([apps/frontend/src/pages/PaymentPage.vue](apps/frontend/src/pages/PaymentPage.vue)) — **today: Gumroad-only, hardcoded URLs per plan** (lines ~140-194). Listens for `window.onGumroadPurchaseComplete` client-side callback to flip `isPaid = true`. No polling, no webhook awareness on the client. After confirmation, downloads via `GET /api/applications/:id/pdf?disposition=attachment`.

4. **Backend** ([apps/backend/src/applications/applications.service.ts](apps/backend/src/applications/applications.service.ts)) — persists the Application row with `status: 'created'`; runs face-match (AWS Rekognition) between license photo and headshot.

5. **Payment confirmation (backend)** — Gumroad → `POST /api/payments/gumroad/webhook?token=...` ([apps/backend/src/payments/providers/gumroad-webhook.controller.ts](apps/backend/src/payments/providers/gumroad-webhook.controller.ts)) → flips `Application.status` to `paid`, optionally emails PDF via Resend.

6. **PDF gating** ([apps/backend/src/applications/applications.service.ts:157-162](apps/backend/src/applications/applications.service.ts#L157-L162)) — if `REQUIRE_PAYMENT_FOR_PDF=1` and status is not `paid`/`pdf_ready` → 403. Otherwise PDF is generated on-demand with `pdf-lib` (no disk cache).

### Prisma schema ([apps/backend/prisma/schema.prisma](apps/backend/prisma/schema.prisma))

One table: `Application`. No `Payment` table — **payment state lives solely in `Application.status`**.

```prisma
enum ApplicationStatus { created  paid  pdf_ready }
```

Gumroad sale metadata is **not persisted** (only emitted as Resend tags). Adding a real audit trail requires a new `Payment` table — worth doing when a second provider (e.g. crypto) lands.

## Known gaps / tech-debt hotspots

Calling these out so an agent doesn't "rediscover" them and churn on fixes:

1. **Payment is Gumroad-coupled.** No `IPaymentProvider` abstraction. URLs are hardcoded on the frontend, single webhook controller on the backend. Adding a second provider (crypto, Paddle) means either (a) a parallel controller + a new frontend branch in `PaymentPage.vue`, or (b) a small abstraction refactor (provider registry + strategy). Pick (b) if you're adding a provider anyway — (a) is a short-term trap.
2. **No `Payment` table.** Gumroad sale_id is only a Resend email tag. Adding a second payment provider = perfect moment to persist `Payment { id, applicationId, provider, externalId, amount, currency, status, raw, createdAt }`.
3. **Webhook auth is a query-string shared secret**, not HMAC. Upgrade to HMAC when touching this area (standard for Paddle; required for most crypto gateways).
4. **No headshot cleanup.** Storage will grow unbounded. Low priority for MVP, high priority post-launch.
5. **German locale missing.** Trivial to add once strings are translated.
6. **PDF gating is a status check in service code.** Fine for MVP. If/when you touch auth, promote to a NestJS Guard.

## Coding rules (from AGENTS.md — condensed)

- TypeScript strict. Avoid `any`. Explicit types preferred.
- NestJS: DTO validation (class-validator).
- Frontend: Zod for runtime validation; vee-validate for forms.
- Respect FSD boundaries — no imports from a higher layer; flag violations, don't silently move files.
- Preserve existing API contracts unless explicitly asked to change them.
- Minimal changes. No new deps unless necessary.
- If unsure about architecture — ask.

### Hosting and deploy

- Landing builds via `nuxt generate` (static) and is deployed to **Cloudflare Pages** (project name `idp-companion-landing`, GitHub repo `flyonkDev/dl-translation-service`).
- **Auto-deploy on push to `master`.** No manual step. Validate prod after push by `curl https://idpcompanion.com/<path>` (apex resolves for any client; www is sometimes blocked by CF for non-verified bots — see Lessons below).
- Both `idpcompanion.com` (apex, CNAME-flattened) and `www.idpcompanion.com` (CNAME → apex) are configured as Custom Domains on the Pages project. Canonical URLs use `www`.

### nuxt-og-image (dynamic per-page OG)

- Module: `nuxt-og-image` configured in [apps/landing/nuxt.config.ts](apps/landing/nuxt.config.ts)
- Templates live at `apps/landing/components/OgImage/*.vue` (rendered via Satori → PNG at request time, cached by CF)
- Per-page usage: `defineOgImageComponent('CountryPair', { origin, destination })` inside the page's `<script setup>` — emits `<meta property="og:image" content="/__og-image__/.../{slug}/og.png">`
- Test locally: visit `/__og-image__/static/<route>/og.png` to inspect the generated image
- Don't fight it — when adding a new country-pair page, just call `defineOgImageComponent`. Generic pages (privacy/refund/terms) use the static `/og-image.png` fallback.

### Country-pair page checklist (when creating a new one)

1. Create `pages/idp-for-{origin}-drivers-in-{destination}.vue`
2. Slug must match URL pattern exactly (lowercase, hyphens, no trailing slash in filename)
3. Add `defineOgImageComponent('CountryPair', { ... })` for OG
4. `useSeoMeta` with full OG/Twitter set + `ogLocale: toOgLocale(locale.value)`
5. JSON-LD blocks: `Article` + `FAQPage` + `BreadcrumbList` + `Product` (use `@id` reference to `${siteUrl}/#organization` for publisher)
6. Use shared [components/FaqAccordion.vue](apps/landing/components/FaqAccordion.vue) for the FAQ section
7. i18n keys go under `pages.<slug>.*` namespace in `apps/landing/i18n/locales/{en,ru,es}.json`. **Locales policy:** Tier 1/2 country-pair pages ship in **EN + the origin's native language** only (e.g., Russia-Thailand = EN+RU; not ES). Skip locales not relevant to the audience via `defineI18nRoute({ locales: [...] })`
8. Internal links: 3 same-origin destinations + 2 same-destination origins + 1 long-form guide. If targets don't exist yet — make them text-only "Coming soon" stubs, **not 404 links**

### Content style (validated 2026-04-25)

- Honest framing — every country-pair page must include a "What IDP Companion is / is not / when it helps / when you need official IDP" block. This is our anti-IDA differentiator and Google E-E-A-T signal.
- All facts (fines, speed limits, alcohol limits) MUST be verifiable. When unsure of date specifics or quoted policy language, soften ("recent amendments" instead of specific dates; "rental chains generally require" instead of citing exact policy text).
- Disclaimer + Sources at bottom — name organizations not affiliated with us, then list source references.
- Word count: Tier 1 = 1500-2500 words; Tier 2 = 800-1500.

### Internal linking conventions

- Footer "Pricing" → `/pricing` (standalone), not `#pricing` anchor on home
- Header "Pricing" → `/pricing` (standalone)
- Home has *both* a `#pricing` anchor (scrolls to widget) AND a "View detailed pricing" link to `/pricing`
- Country-pair → 3 same-origin (e.g., Russia→Turkey, Russia→UAE) + 2 same-destination (e.g., US→Thailand, German→Thailand) + 1 guide. **Always render even if targets don't exist yet** as "Coming soon" stubs (text, no `<a>`).

## Lessons learned (from Phase 0 buildout)

- **Domain stack is fragile.** Canonical URLs were `www.idpcompanion.com` while DNS had no `www` record — Google saw NXDOMAIN for everything. Fix required: (a) add CNAME `www` → apex in Cloudflare DNS, (b) register `www.idpcompanion.com` as Custom Domain in Cloudflare Pages project. Both steps are needed; DNS alone returns 522.
- **Cloudflare's "Manage robots.txt" silently overrides** the static file from `public/robots.txt`. Always check what's actually being served (`curl /robots.txt`) — disable Cloudflare's robots.txt management to keep the static file authoritative.
- **Telegram preview-bot caches OG previews ~2 days.** Use @WebpageBot or append `?v=N` query to bust. New OG tags require this even after deploy.
- **`og:locale` must be `xx_XX` format**, not just `xx`. Use `toOgLocale()` helper.
- **GSC "Couldn't fetch" sitemap is initial state**, not always an error. Google retries on its own schedule. URL Inspection's "Couldn't fetch" with DNS error means real problem.
- **GSC negative DNS cache holds for hours.** After fixing DNS, expect 1-4h before URL Inspection updates. Don't request indexing during this window — it queues against the bad cache.
- **Anthropic-IPs are blocked by Cloudflare's default Bot Score** for proxied hosts (oranges). For diagnostics from Claude Code, fetch via apex (often grey-cloud or routed differently) — `curl https://idpcompanion.com/...` works where `www.` doesn't from the Anthropic side.
- **Windows shell tool quirks:** `curl` is an alias for `Invoke-WebRequest` in PowerShell — use `curl.exe` for real curl. Bash on Windows is fine for unix-style commands.
